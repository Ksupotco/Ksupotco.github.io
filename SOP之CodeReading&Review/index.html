如何阅读源码（尤其是论文代码）

后者是前者的子集，so阅读源码有一套通用的范式可以应用在论文代码上。而且后者一般代码量比较小，还有论文原文来解释机制和模块,所以是不是感觉自己工作量更少了。这里先mark几篇我读起来特别好的文章。

如何阅读一份代码
https://gist.github.com/baymaxium/bd9932b7288aac6e5f7b510624b8b3e6
我们阅读代码，首先要能读懂，其次是从中学习优秀代码的架构方式。读懂是一个过于宽泛的概念，在这里我们把它定义成建立一个完成当前任务的模型，并且据此预测代码行为。也就是说，至少我需要能够回答“给它什么，它会经过什么过程，在什么条件下改变什么状态，最终产生什么结果；如果我要改某个行为，应该改哪里？”类似这些问题。
那么我们会思考，一份项目源码通常是由什么组成的。在这里我们提炼出：

Program=input+transformers+state+control+output

     Control
        ↓

Input → Transformation → Output
↕
State

那么现在我们至少可以确定接下来要关注什么。下一步就是思考怎么才能够从源码中得到我们想要的上述信息。
我们以一个小仓库为例来展示和练习。

1. 模块依赖与对象关系

看到的代码 语法层 架构层应该想到
import X 导入模块 当前模块可能依赖 X
from X import Y 导入 Y 当前模块直接依赖 X.Y
x = X() 创建对象 当前模块负责构造 X
self.x = X() 保存对象 当前对象拥有 X，通常是 Composition
self.x = x 保存外部对象 X 可能通过 Dependency Injection 注入
A(B) 继承 A 是 B 的一种特殊实现
class A: 定义对象 一个职责/领域概念/服务的边界
@abstractmethod 抽象方法 定义接口，实际实现可以替换
Protocol / ABC 接口约束 存在插件式/可替换架构
isinstance(x, X) 类型判断 行为根据具体实现分叉
super().foo() 父类调用 当前实现扩展基础行为

源码 不要停留在 应该进一步读成

db.xxx() 数据库 Application ↔ Persistence
